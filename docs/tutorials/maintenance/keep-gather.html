First day — in order

Do these once on a laptop that does not have Gather yet.

  1. Fill the address card

    Open the team project card. Confirm the web address and the daily line (usually experiment). If names still say placeholders, ask the owner to fill them.

    Done when you can open the project page — or you know you still need an invite.

  2. Your own GitHub login

    Use your account. Ask the owner to invite your username to the central home. Accept as yourself. Never share passwords.

    Done when the project opens while you are signed in as you.

  3. Tools on the counter

    Install Cursor, Git, and Node 20 or later. In Cursor, sign in to GitHub as you. Check versions in the terminal.

    Done when git --version and node --version both print a number.

  4. Copy the notebook onto your desk

    Clone the daily line into a gather folder. In Cursor: File → Open Folder → that folder.

    Done when git status says you are on experiment.

  5. Private settings (drawer keys)

    Copy .env.example to .env. Put long random text in the secret fields. Keep the local web address as localhost for now. Never commit this file.

    Done when .env exists privately and is not in the “files to save” list.

  6. Open the shop on this laptop

    Run install, prepare the data file, seed once, then start the app. Open http://localhost:3000. Do not read seed passwords aloud or paste them into chat.

    Done when the Gather sign-in page loads.

  7. You decide; the helper helps

    Open Chat in Agent mode. Ask for a short plan before edits. Read proposed changes before you say yes.

    Done when you have a plain plan and no surprise saves.

  8. Learn save, share, ask for a check

    Save = commit on this laptop. Share = push to the shelf. Ask for a check = open a pull request onto experiment. You say the words.

    Done when you can point at those three ideas without rushing.

  9. Leave the live shop alone today

    The public window is a later, owner-only job. Practice on the laptop first.

    Done when you have not opened the server door.

Every work day — in order

Start here once the Gather folder already opens on this laptop.

  1. Get other people’s pages first

    Check out the daily line, then pull with a fast-forward only. Collect the post before you write.

    Done when status is clean and up to date.

  2. Name one small job

    Write the bug or change in everyday English. Ask for a three-step plan, then wait.

    Done when you have a plan before files change.

  3. Smallest change, then check

    After you say go: change only what the plan named. Run the tests and the type check. Add a changelog line if people will notice.

    Done when checks pass and the screen looks right.

  4. Save — only when you say “commit”

    Review the file list. Never add .env. Write a short reason in the save message.

    Done when today’s page is written on this laptop.

  5. Share, then ask for a check

    Push when you say push. Open a pull request onto experiment with a short summary and a test plan. Comment kindly on the letter.

    Done when the web project shows your work.

  6. Live shop only when an owner asked

    A normal day ends at the shelf. Updating the public window is a separate path below.

    Done when you either stop at GitHub, or continue on purpose as an owner.

Live shop (owners)

Only An / Guillaume — or whoever holds the shop key. Code must already be on the GitHub shelf.

  1. Confirm the shelf has the pages

    The short commit on GitHub must match the change you mean to publish. Save and share first if it does not.

    Done when the shelf shows the right pages.

  2. Confirm you have the shop key

    SSH is a private door key on this laptop. Do not paste it into chat or onto a slide.

    Done when the key file is present — or you stopped because it is missing.

  3. Open the door

    Connect to the rented computer, then move into the Gather app folder.

    Done when you are inside the app folder on the server.

  4. Fetch the new pages

    Pull the daily line with a fast-forward only. If it cannot, stop.

    Done when the pull succeeds with no clash.

  5. Rebuild and restart

    Install locked ingredients, generate, build, then restart the Gather service.

    Done when build and restart finish without a red failure.

  6. Check the short code and the window

    Compare the short commit on the server to GitHub. Hard-refresh the live site (or use a private window).

    Done when the site shows the new behaviour.

  7. Leave the older demo host alone

    Do not push this SQLite build to Railway while that host still expects the old database.

    Done when only the intended live shop was updated.

Clear stills for guides and slides

Same calm rules as a good film take — one idea per picture.

Capture

On a Mac: ⌘⇧4 and drag a tight rectangle. Prefer one window. Browser zoom about 125%.

Stay sharp

Keep the full Retina size. Do not shrink a screenshot and then enlarge it later — that goes soft.

Trim

Open in Preview. Crop to the title and the one action. Soft blur any secret with Markup.

Name

Plain filenames in order: 01-github-home.png, 06-localhost-signin.png.

Never in frame

Passwords, filled .env, seed output, real member names or cell numbers.

Look

Soft plain desktop. Same browser width across a sequence. No busy wallpaper fighting the text.

Recording the path on this MacBook. Free and built in: press ⌘⇧5, choose Record, pick your microphone under Options. QuickTime Player → File → New Screen Recording works the same way. For longer films with scenes, OBS Studio is free. Trim silence later in iMovie (free).

When something feels stuck

Open a question. If the answer still fails, copy the exact message into Cursor and wait — do not invent a forceful fix.

Accounts and access

The project page says 404 or access denied

You may not be invited yet, or the address card still has placeholders. Tell the owner your GitHub username. Do not guess a new team address.

Should I share one GitHub login with the team?

No. Everyone uses their own login — like their own house key. The shared notebook lives under the central team home; you get invited there.

I accepted an invite but clone still fails

Sign out and back into GitHub in the browser and in Cursor as the same person. Confirm you open the central project URL, not a private copy you invented.

What is the difference between me and the central home?

You are the person signing in. The central home owns the shared repo. Comments and reviews show your name; the files still live on that one shelf.

Tools and first setup

The terminal says command not found for git or node

Install that tool, quit the terminal fully, open a new one, try again. Cursor’s terminal and the Mac Terminal both need a fresh start after installs.

Which editor should I use?

Cursor — it is the place the team expects, with the chat helper. Open the same Gather folder you cloned.

Do I need Postgres on my laptop?

No for local Gather. This path uses a SQLite file on disk. Follow the example settings file.

Port 3000 is already in use

Another npm run dev may still be running. Stop it, or ask the helper which process holds the port. Then start again.

Where do the first passwords appear?

Once in the terminal when you seed. They are not shown in the app. Do not put them in chat, a pull request, a comment, or a film.

Can I commit the .env file so others have it?

No. That file is drawer keys for one machine. Share the example file only. Each person makes their own private copy.

Daily line and GitHub words

Why experiment and not main?

Daily work lives on the daily line (usually experiment). main stays quiet until a human owner asks. Base review letters on the daily line.

What does save / share / ask for a check mean?

Save = commit on your laptop. Share = push to the shelf. Ask for a check = open a pull request. You must say those words; the helper waits.

git status says I am on main

Switch to the daily line without deleting work. Ask the helper to move you safely. Do not start daily fixes on main.

Pull says it cannot fast-forward

Stop. Paste the full message into Cursor. Do not invent a rebase. Do not force-push.

Git says we both wrote on the same line

Two cooks on one recipe card. Copy the red text, paste it into Cursor, ask for plain options, and wait. No force-push to main.

I typed in the wrong file and have not saved yet

Restore that one file if you are sure. If you already committed, do not invent scissors — ask with git log and status on screen.

Push was rejected

Get other people’s pages first (fast-forward pull), then push again. Never force-push main.

Nothing to commit

Nothing was staged, or nothing changed. Review the file list with the helper before you try again.

Checks, reviews, and kindness

Tests or typecheck failed

Paste the red lines into Cursor. Do not skip the checks to “save time.” A failing check is the soup tasting off before service.

How do I leave a comment on someone’s change?

Open the pull request on the central project. Use Files changed. Point at a line. Be specific and kind. Your name shows on the note.

Should I approve if I only skimmed?

No. Read Files changed first. If you are unsure, leave comments only. Owners still decide merges.

Someone asked for changes on my letter

Fix on your laptop, save, share, reply on each thread what you did, then ask for another look.

Can the chat helper commit alone?

No. You say commit, push, and pull request. That keeps the official book honest.

Live shop and demos

The live site looks old after an update

Hard-refresh or open a private window. On the server, check the short commit matches GitHub. If it does not, the pull did not land.

SSH says permission denied

Wrong key or missing invite to the key. Stop. Do not guess passwords. Ask the owner who holds the shop key.

Should I update Railway with this build?

Not while Railway still expects the older database. Oracle is the SQLite shop window for this path. Ask an owner before touching Railway.

Is the live shop part of day one?

No. Day one ends when the laptop shop opens and you understand save, share, and check.

Meetup events look empty

Use a Birmingham find page in the priority list, then Run now — not only the bare homepage. Ask an admin if you cannot see scraper settings.

Safety and calm

What must never go into a commit or comment?

Passwords, .env, seed secrets, and real member data. If you see them in a diff, request changes and stop.

Someone suggests force-push to main

Say no. Tell the project owner. Force-pushing main rewrites the official book.

I feel out of my depth

Run git status. Copy the exact message. Paste into Cursor. Ask for plain options and wait. One step is enough for today.

Where is the fuller recipe if I want to read?

In the repo under docs/tutorials/maintenance/ — start at the README door, then the from-scratch lesson, Git in pictures, and comment guide.

Can I print this page?

Yes. Use the browser print dialog. Answers stay readable on paper.

How do I share this guide with someone?

Send this HTML file, or open it from the repo path docs/tutorials/maintenance/keep-gather.html. It works offline in a normal browser.
